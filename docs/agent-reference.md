# Agent reference

Non-obvious details of the code: gotchas, invariants, and why some tests exist. Read the
section for the area you touch. Behavior belongs in the [spec](spec/README.md); this file
is about the code.

## Workspace and tooling

- **Integration tests and clippy.** `clippy.toml` allows `unwrap`/`expect`/`print` in
  tests, but that does not cover helper functions in integration-test crates
  (`crates/*/tests/*.rs`). Those files start with
  `#![allow(clippy::unwrap_used, clippy::expect_used)]`.
- **Toolchain pin.** `rust-toolchain.toml` pins the version CI uses. It only applies under
  rustup; a system `cargo` earlier on `PATH` ignores it.
- **Licences.** `deny.toml` is the enforced allowlist (AGENTS.md list plus `Unicode-3.0`).
  Run `cargo deny check licenses bans sources` after adding a dependency.

## Protocol (`crates/kumikit-protocol`)

- **The local address lives here** (`local.rs`), so the core and the desktop shell compute
  the same socket or pipe. It stays pure: the environment and user id are passed in.

- **The method table is a macro** (`methods!` in `methods.rs`). Dispatch in
  `kumikit-core/src/rpc.rs`, TypeScript generation and the fixture coverage test all walk
  it. A new method goes there first; `rpc::tests::every_method_is_routed` fails until the
  core dispatches it.
- **TypeScript is generated by a test.** `tests/typescript.rs` regenerates `web/protocol/`
  into a temp dir and compares. `KUMIKIT_BLESS=1 cargo test -p kumikit-protocol` rewrites
  it. The generator maps 64-bit integers to `number` (ts-rs defaults to `bigint`).
- **Fixtures.** See [the fixtures README](../crates/kumikit-protocol/tests/fixtures/README.md).
  `KUMIKIT_RECORD=<dir> cargo test -p kumikit-core --test exit_m0` writes fresh
  transcripts; scrub ids, times, paths and host names before committing them.
- **Unknown error codes** deserialize as `ErrorCode::Internal`, as the spec asks.

- **`kumikit_protocol::remote`** holds the pure rules both sides print and read: the
  fingerprint format, pairing-code normalising, `host[:port]` parsing, the close code and
  token prefix.

## Kernel (`crates/kumikit-kernel`)

- **One writer.** `store::Store` sends write closures to a single writer thread, which
  runs everything queued in one transaction, each closure in its own savepoint. Closures
  must not commit or begin transactions themselves. A write returns only after the commit
  (`synchronous=FULL`).
- **`seq` is assigned in `repo::append_event`**, from `threads.head`, inside the writer.
  Derived columns (thread status, turn end, approval status) are updated in the same
  call; `fold::next_status` is shared with `thread.get`'s fold so both agree, and
  `kernel::tests::snapshot_matches_derived_status` checks it.
- **Subscriptions tail the log.** A `ThreadSubscription` marks the head `watch` as seen
  *before* each read, then waits for it to change. Heads are bumped only after commit.
  This ordering is why there is no gap or duplicate; keep it if you touch
  `next_batch`.
- **Approvals race by design.** The log arbitrates: resolving appends
  `approval.resolved` only if the row is still `pending`, so the loser gets `conflict`.
  Providers can get an answer before `request_approval` returns (see the `Provider`
  docs); the WASM adapter (`SessionShared`) and the test fakes keep early answers.
- **Kernel close abandons turns.** `Kernel::close` drops running turns without writing
  `turn.ended`; the next `Kernel::open` ends them as `core_restarted`. Tests rely on this
  being deterministic.
- **Process supervisor** (`process/`). A child's tree is killed when its last `Child`
  handle drops, when its owner is killed, or at shutdown. Tests prove a whole tree died
  by reading stdout to EOF: `fake-acp-agent tree` gives a grandchild the same stdout, so
  EOF means every holder exited (no sleeps). The core's environment is injected
  (`SupervisorConfig::env`), so tests control `PATH`.
- **Devices** (`devices.rs`) store only the token's hash. Revocation deletes the row, then
  broadcasts the id; a listener that lags must check `device_exists`, not trust the
  broadcast.
- **Time and ids are injected** (`KernelConfig { clock, ids }`); tests use `StepClock`
  and `SequentialIds`.

## Plugin host (`crates/kumikit-plugin-host`)

- **`.kkp` code is in `kumikit-package`**, re-exported as `kumikit_plugin_host::package`,
  because the shell unpacks UI plugins and may not depend on the plugin host.

- **The call-time limit and the call hook.** The limit is measured from the last time the
  guest entered wasm or returned from a host import (`engine::apply_limits`). wasmtime
  runs the epoch deadline callback as a host call, so the call hook sees
  `ReturningFromHost` after every tick; the callback sets `in_deadline_callback` so that
  return does not reset the clock. Without it a spinning guest never traps
  (`tests/runtime.rs::running_past_the_call_limit_traps` hangs).
- **Instances are actors** (`runtime::Instance`): a task owns the `Store` and runs calls
  one at a time from a channel, so a caller that stops waiting never interrupts a guest
  mid-call. Anything that must reach a guest during `send` (approval answers, cancel)
  goes through `SessionShared`, which the blocking imports select on.
- **Providers are reconciled, not patched** (`lifecycle::PluginHost::reconcile`): after
  every enable, disable or uninstall the host recomputes the providers the enabled
  plugins offer and registers or unregisters the difference. A session that finishes
  starting after its provider was removed discards itself (`start_session` checks the
  registration), because the kernel appends `turn.started` before it starts a session.
- **`send` runs in its own task**, so the kernel dropping its future on cancel never
  interrupts the guest; the session's `busy` flag tells the grace-period timer whether
  to discard it.
- **Test components in WAT**: an imported instance with no exports is satisfied
  without a definition; give it a function to test a missing import.

## Shell (`crates/kumikit-shell`)

- **Logic in the library, wiring in `main.rs`.** Asset serving, the CSP, finding and
  starting the core and the bridge are plain modules with tests that need no window.
- **Commands need a capability.** `build.rs` declares the app's commands, so Tauri refuses
  any that `capabilities/*.json` does not grant to the window. A new command goes in both.
- **Shell tests find `kumikit`** by walking up from the test executable (cargo puts test
  binaries under `build/` in 1.100). `cargo test --workspace` builds it; `-p
  kumikit-shell` alone does not, and the tests say so.
- **Installer config is separate.** `tauri.bundle.conf.json` (resources and the bundled
  core) is merged only by the installer build (`tauri build --config …`), so plain cargo
  builds need neither `target/bundle` nor the core binary. Before it: `node
  scripts/bundle.mjs`, and the release core copied to `binaries/kumikit-<target triple>`.
- **The AppImage is repacked** (`scripts/repack-appimage.mjs`) after Tauri builds it: the
  bundled Wayland libraries are dropped (with Mesa 25+ hosts they leave WebKit unable to
  create an EGL display, so the window stays blank) and the GTK hook's `GDK_BACKEND=x11`
  becomes a default. If Tauri changes the hook, the script fails instead of guessing.
  `scripts/smoke-appimage.sh` proves the result starts: the shell starts the core only
  when the UI kernel's JavaScript connects.
- **Remote profiles** (`connections.rs`) are what the Tauri commands and the test relay
  both call; `main.rs` only wires them. The token never leaves `secrets.rs` and
  `remote.rs`: the shell sends `auth.token` itself before attaching the WebSocket.
- **A child's stdin does not close on `shutdown`.** For SSH the bridge takes ssh's stdout
  and stdin as separate halves (`attach_halves`) and drops stdin when writing ends;
  `io::join` plus `split` kept it open and deadlocked the far side's `kumikit bridge`.
  ssh's stderr can arrive after its stdout closes, so failures wait (2 s at most) for it.
- **The keychain path is tested on Linux** against `keyring_core::mock`; only the
  macOS and Windows store constructors (and the real-keychain test) run in CI alone.
- **Window tests run in a container** (`sh scripts/desktop/run.sh <cmd>`): Ubuntu, Xvfb,
  WebKitGTK and its WebDriver. Builds there use `target/desktop-container`.

## Test tools (`test-plugins/`)

- **`net-cut`** is a loopback proxy whose `cut` is a black hole (nothing passes, nothing
  closes) and whose `restore` closes every connection from before the cut. It uses
  epochs, so a connection whose task never saw the cut is still closed; while cut it does
  not accept, so new connections wait in the backlog. The relay embeds it; the desktop
  test drives the binary over stdin.
- **`fake-ssh`** stands in for `ssh` (`KUMIKIT_SSH`): it skips ssh's options, ignores the
  destination and runs the remote command locally; the destination `denied` fails like
  ssh does.
- **The relay** (`web-relay --remote`) runs a second core behind `net-cut` and serves the
  shell's profile commands with the shell's own `connections` code. Its bridge socket's
  first message is `{"type":"open"}` or `{"type":"error",…}`, like `bridge_connect`.

## UI kernel (`web/kernel`)

- **State is `.svelte.ts` classes; logic is plain functions** (`threads/fold.ts`,
  `commands/registry`, `theme/validate`) tested in Vitest without a DOM. Tests use
  `tests/fake-core.ts` (an in-memory core) and injected timers and frame schedulers, so
  nothing waits on real time.
- **One wire subscription per topic** (`CoreConnection.subscribe`): listeners keep their
  own cursor, a late listener replays the topic and the others skip what they have.
- **The status fold must match the kernel's.** `crates/kumikit-kernel/tests/fixtures/
  status.json` is checked by both `status_fixture.rs` and `web/kernel/tests/fold.test.ts`.
- **The platform is a build-time constant** (`__KK_PLATFORM__`): `vite build` gives the
  desktop bundle, `--mode browser-test` the one with the test relay adapter.
- **No inline styles or `<style>` elements**: the CSP forbids them. The theme engine
  writes a constructed stylesheet (`adoptedStyleSheets`). `scripts/check-ui-rules.mjs`
  catches literal colors, radii, font sizes, shadows and IME-unsafe Enter/Escape.
- **Several connections.** `kernel.connection` is the active tab's (or the home one), so
  code written for one core follows the tab. Threads are keyed by the whole address.
  `requires.core` gating goes through `kernel.slotsIn`, `rendererFor` and
  `commandAllowed`; use those, not `slots.in`, for anything a plugin contributes.
- **Playwright failure snapshots are taken during teardown.** The page may already show
  the connection closing; check the core's debug log (`KUMIKIT_LOG=kumikit_core=debug`
  logs each request's method and duration) and, for Chromium, `KK_NETLOG=<file>` before
  concluding a connection dropped. A palette command whose `when` is not yet true (for
  example "New thread" before a tab exists) matches nothing: wait for the state first.
- **Read props before closing a dialog.** A component's props are gone once it unmounts,
  so a dialog that closes itself and then acts must copy them first (`OpenFolder`).
- **`props` is a reserved name in components**: `$props` would read as a store
  subscription of a variable called `props`.

## Core (`crates/kumikit-core`)

- **Providers come only from plugins** ([ADR 0011](decisions/0011-providers-from-plugins.md)).
  `serve::open_core` opens the kernel, the plugin manager and the plugin host; the CLI's
  offline path uses it too. Core tests use the probe test plugin
  (`test-plugins/probe`, installed through `plugin.install` by `tests/support`); unit
  tests in `rpc/tests.rs` use a fake provider defined in the test module.
- **End-to-end ACP tests** (`tests/exit_m1.rs`) run `fake-acp-agent replay
  <transcript>` as the agent, found on the core's `PATH` (`Core::start_with_path`). The
  fake checks each client message's method in order and rewrites the recorded
  `/workspace` to its working directory. The probe's manifest is
  `test-plugins/probe/plugin.toml`, read by the tests and by `check-plugin-names.sh`.
- **Test client notifications.** `tests/support::Client::event` sets aside
  notifications other than `events.event` (`core.pluginsChanged`); read them with
  `Client::notification`.
- **Socket paths are short.** Unix socket paths are limited to about 104 bytes. Tests
  use `/tmp/kkXXXX/s.sock`, chmod the directory to 0700 (tempfile follows the umask,
  often 0755) because the core refuses non-private directories.
- **Readiness.** `kumikit serve` prints `ready <address>` on stdout once it accepts
  connections; the test harness (`tests/support`) waits on that line instead of
  sleeping.
- **`unsafe` lives only in `transport/windows.rs`** (Win32 security descriptor for the
  pipe DACL) and `kumikit-kernel/src/process/windows.rs` (job objects). The workspace
  lint is `deny`, allowed on those modules alone. Each block has a `SAFETY:` comment.
- **Workspace topics** (`pump_workspace` in `rpc.rs`) read a kernel broadcast of thread
  changes, taken before the workspace check so nothing after the result is lost. Only
  status-changing kinds (`turn.started`, `approval.*`, `turn.ended`) announce
  `thread.updated`. A lagging listener resends every thread rather than dropping changes.
- **`core.shutdown`** sets a flag; the connection closes after its reply is written and
  only then notifies the serve loop, so the client always gets the answer.
- **Bundled plugins** (`bundled.rs`) seed after `ready`, in file-name order; ids are
  remembered in `seeded_plugins` (migration 3) so removals stick.
- **One message loop for every transport.** `rpc::serve_messages` reads and writes whole
  messages through `messages::{MessageReader, MessageWriter}`: lines (`LineReader`) for
  sockets, pipes and `kumikit bridge`, WebSocket frames (`remote::ws`) for remote clients.
  Its `stop` future (a device's revocation) is polled next to `recv`, so a reader that is
  not cancel-safe (lines) gets a `stop` that never resolves.
- **The remote gate is not server state.** `remote::gate` reads and answers a remote
  connection's first message itself; `serve_messages` is built only for an authenticated
  device, so no kernel method can run before authentication. Browsers authenticate in the
  upgrade (cookie, same origin) instead. Non-WebSocket requests free their connection's
  pre-auth place at once.
- **Remote tests shorten time** with hidden `serve` flags (`--pre-auth-ms`,
  `--keepalive-ping-ms`, `--keepalive-idle-ms`) and wait for the core to act; the shell's
  test builds take `KUMIKIT_TEST_KEEPALIVE=<ping ms>,<idle ms>`.
- **Subscription result before events.** `rpc.rs` queues the `events.subscribe` result,
  then starts the pump (`Conn::deferred`). Starting the pump inside the handler would
  let an event overtake the result.
