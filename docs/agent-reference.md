# Agent reference

Non-obvious details of the code: gotchas, invariants, and why some tests exist. Read the
section for the area you touch. Behavior belongs in the [spec](spec/README.md); this file
is about the code.

## Workspace and tooling

- **Integration tests and clippy.** `clippy.toml` allows `unwrap`/`expect`/`print` in
  tests, but that does not cover helper functions in integration-test crates
  (`crates/*/tests/*.rs`). Those files start with
  `#![allow(clippy::unwrap_used, clippy::expect_used)]`.
- **Toolchain pin.** `rust-toolchain.toml` pins the version CI uses. It only applies under
  rustup; a system `cargo` earlier on `PATH` ignores it.
- **Licences.** `deny.toml` is the enforced allowlist (AGENTS.md list plus `Unicode-3.0`).
  Run `cargo deny check licenses bans sources` after adding a dependency.

## Protocol (`crates/kumikit-protocol`)

- **The method table is a macro** (`methods!` in `methods.rs`). Dispatch in
  `kumikit-core/src/rpc.rs`, TypeScript generation and the fixture coverage test all walk
  it. A new method goes there first; `rpc::tests::every_method_is_routed` fails until the
  core dispatches it.
- **TypeScript is generated by a test.** `tests/typescript.rs` regenerates `web/protocol/`
  into a temp dir and compares. `KUMIKIT_BLESS=1 cargo test -p kumikit-protocol` rewrites
  it. The generator maps 64-bit integers to `number` (ts-rs defaults to `bigint`).
- **Fixtures.** See [the fixtures README](../crates/kumikit-protocol/tests/fixtures/README.md).
  `KUMIKIT_RECORD=<dir> cargo test -p kumikit-core --test exit_m0` writes fresh
  transcripts; scrub ids, times, paths and host names before committing them.
- **Unknown error codes** deserialize as `ErrorCode::Internal`, as the spec asks.

## Kernel (`crates/kumikit-kernel`)

- **One writer.** `store::Store` sends write closures to a single writer thread, which
  runs everything queued in one transaction, each closure in its own savepoint. Closures
  must not commit or begin transactions themselves. A write returns only after the commit
  (`synchronous=FULL`).
- **`seq` is assigned in `repo::append_event`**, from `threads.head`, inside the writer.
  Derived columns (thread status, turn end, approval status) are updated in the same
  call; `fold::next_status` is shared with `thread.get`'s fold so both agree, and
  `kernel::tests::snapshot_matches_derived_status` checks it.
- **Subscriptions tail the log.** A `ThreadSubscription` marks the head `watch` as seen
  *before* each read, then waits for it to change. Heads are bumped only after commit.
  This ordering is why there is no gap or duplicate; keep it if you touch
  `next_batch`.
- **Approvals race by design.** The log arbitrates: resolving appends
  `approval.resolved` only if the row is still `pending`, so the loser gets `conflict`.
  Providers can get an answer before `request_approval` returns (see the `Provider`
  docs); the scripted provider and the test fake keep early answers.
- **Kernel close abandons turns.** `Kernel::close` drops running turns without writing
  `turn.ended`; the next `Kernel::open` ends them as `core_restarted`. Tests rely on this
  being deterministic.
- **Time and ids are injected** (`KernelConfig { clock, ids }`); tests use `StepClock`
  and `SequentialIds`.

## Core (`crates/kumikit-core`)

- **`scripted_provider.rs` is temporary** ([ADR 0009](decisions/0009-temporary-scripted-provider.md)).
  It is the only provider id in `crates/`; M1 deletes it and its registration in
  `serve.rs`.
- **Socket paths are short.** Unix socket paths are limited to about 104 bytes. Tests
  use `/tmp/kkXXXX/s.sock`, chmod the directory to 0700 (tempfile follows the umask,
  often 0755) because the core refuses non-private directories.
- **Readiness.** `kumikit serve` prints `ready <address>` on stdout once it accepts
  connections; the test harness (`tests/support`) waits on that line instead of
  sleeping.
- **`unsafe` lives only in `transport/windows.rs`** (Win32 security descriptor for the
  pipe DACL). The workspace lint is `deny`, allowed on that module alone. Each block has
  a `SAFETY:` comment.
- **Subscription result before events.** `rpc.rs` queues the `events.subscribe` result,
  then starts the pump (`Conn::deferred`). Starting the pump inside the handler would
  let an event overtake the result.
